An object names a VIP; it never names an address. The one it gets when it names none is {{ cluster.default_vip }} — changing that moves traffic for every site that never said anything, so it will ask again before writing and say how many objects come with it.

Adding a virtual address here does half the job. The other half is keepalived on the nodes, which this application does not configure. No node carries the address until someone adds it to the virtual_ipaddress block, and until then no traffic reaches the frontend however correct the generated configuration is.

None. Every object leaves from its VIP's default.

HAProxy takes the source per backend rather than per listener, so a site may leave from a different address than the one it arrived on. Each VIP above already names a default; this table is the exception, and an exception should have to be named. A NetScaler calls these SNIPs.

A source address must sit in the same keepalived block as its VIP. Replies come back to whichever node currently holds the address, so one that does not move together with the VIP answers into a void after a failover — and looks correct until then.
